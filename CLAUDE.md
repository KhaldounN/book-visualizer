# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Book Analyzer: upload an English novel (`.txt`) and get its characters, mention counts (names + pronouns), per-sentence sentiment and emotions, key moments, character relationships, places, and how all of these change chapter by chapter. Several ideas came from the owner's 2020 project (github.com/KhaldounN/book-analyzer-beta), reimplemented. A pure-Python analysis engine (`analyzer/`) plus a Streamlit website (`app/`). The owner is learning programming: explain changes simply.

## Architecture

`pipeline.analyze(bytes, progress)` runs the steps in order and returns a `BookAnalysis` (`analyzer/models.py`):

1. `loaders.load_text`: decode, strip the Project Gutenberg licence, remove `[Illustration…]` blocks (but keep a chapter heading or "THE END" hidden inside one), cut back matter after "THE END", and join wrapped lines so every paragraph is one line.
2. `segment.split_sentences`: spaCy `en_core_web_lg` over each paragraph produces sentences with their entities. Text before the first `CHAPTER …` heading (preface, contents) is dropped. Books without headings are split into 50 equal parts.
3. `characters.find_characters`: PERSON entities become characters. The title before a name separates people (Mr./Mrs./Miss Bennet are three characters). Name forms are grouped from most specific to least (full names, then titled names, then bare names). One "follows a place word" rule (`_after_place_word`: `in/at/from/the…`) removes places tagged as people (Meryton) *and* turns ORG estates into places (Netherfield, Pemberley). Plural surnames ("the Lucases") become groups. Entities keep per-chapter counts.
4. `coref.resolve`: fastcoref `FCoref` runs on ~1,500-word chunks, each with ~250 words of read-only context in front. A coreference group is credited to the character whose names dominate it. I/you/they/it words and forms of address are skipped, and pronouns of the wrong gender are dropped (gender comes from titles, else from the 3:1 pronoun ratio).
5. `sentiment.score_sentences`: each sentence gets P(positive) − P(negative) from `cardiffnlp/twitter-roberta-base-sentiment-latest`.
6. `emotions.detect_emotions`: `lrei/roberta-base-emolit` (trained on Gutenberg sentences) scores 38 fine emotions independently (multi-label, so `classifier.py` uses sigmoid for it and softmax for the sentiment model, chosen from the model config's `problem_type`). Each sentence keeps `fine` (only emotions >= 0.1) and `emotions` = 8 `FAMILIES` (each the strongest member scored >= `PRESENT` = 0.5; weaker scores made all chapters look alike) plus `neutral` = 1 − the strongest family; the 5 `CALM` feelings belong to no family. Charts use families; `stand_out()` names fine emotions at least 1.25× the book's average (character and chapter cards). Steps 5 and 6 share `classifier.py` (model loading + length-sorted batching).
7. `chapter_events.name_chapters`: per chapter, TF-IDF keywords, the key sentence richest in them (the "event"), and a theme from `THEMES` picked by `all-MiniLM-L6-v2` embeddings of the key sentences vs. theme descriptions, z-scored per theme over the book (otherwise one theme wins everywhere). Everything is local by the owner's choice: no external APIs. A zero-shot NLI classifier was tried and rejected (no better, ~2 h per novel on this PC).
8. `relationships` / `progression`: per-chapter aggregates and emotion averages (`emotions.average_emotions`, which lives in `emotions.py` to avoid a circular import). Two characters are "together" when mentioned in the same or the next sentence of the same chapter; each pair also keeps an emotion mix per third of the book. `progression.rolling_sentiment` / `key_moments` / `story_arc` (turning points, acts) are computed in the app at render time, not stored.

9. Render-time extras (no model, no re-analysis, from the saved sentences and mentions): `dialogue.find_lines` rebuilds paragraphs from the sentence offsets (sentences 1 character apart, paragraphs 2+), takes the text between quotation marks as `Line`s (one paragraph = one speaker's turn; an unclosed quote runs to the paragraph end), and finds speakers: `said` (a speech verb within `NEAR` characters of a name), `pronoun` (the same with a coref pronoun: only ~6 in 10 right, because coref gives "she" to the heroine, so `strongest_lines` uses `said` turns only), `before` (one character named before the quote) and `turn` (A, B, A in three consecutive paragraphs). Possessives (*said her father*) never speak. The listener is the neighbouring turn's other speaker. Hand check on P&P: said 10/10, pronoun 6/10, turn 7/10. `pace.py`: reading time (230 wpm), words per sentence, Flesch-Kincaid grade (vowel-group syllables), MATTR richness (100-word window), dialogue share, and action = verbs / (verbs + adjectives) from `Sentence.tags` (word types counted by `segment.word_types` during step 2; a None class default so old pickles load; `scripts/add_word_types.py` fills them into saved results in ~1 min, no version bump). `pace_scores` = mean z-score of short sentences, dialogue and action within the book.

Title and author come from `loaders.book_info` (the Gutenberg `Title:`/`Author:` header lines, else the filename).

Key invariants:
- **Every `start`/`end` is an offset into the cleaned text** from `load_text`, and tests assert `text[start:end] == mention.text`. Keep it that way.
- **Character ids are list indexes**, `0..n-1`. `merge.merge_characters` renumbers them and recomputes relationships and progression. Never cache anything keyed by old ids across a merge.
- **Models are injectable** for tests. `coref.resolve` takes a `model` with `.predict`; `sentiment.score_sentences` and `emotions.detect_emotions` take a `classify(list[str])` function.
- **Bump `pipeline.ANALYSIS_VERSION`** whenever `BookAnalysis` or the analysis changes: cached results are `results/v{N}-{sha256}.pkl`, so old ones are then ignored instead of loaded with missing fields. Tests use fakes (`tests/test_coref.py::FakeModel`), and `tests/test_pipeline.py` monkeypatches the `load_model` functions.
- The pipeline loads **one AI model at a time** and deletes it with `gc.collect()` before loading the next.

### Website (`app/`)

- `streamlit_app.py` is re-run top to bottom on every interaction. Analyses live in `st.session_state["analyses"][sha256]` with the user's merges, which are applied at render time. Finished analyses are pickled to `results/v{ANALYSIS_VERSION}-<sha256>.pkl`; the uploaded text itself is never saved.
- **One scrolling dashboard, no tabs** (the owner's choice). The sidebar holds upload, title, merging, the character-colour legend and "Jump to" links. The main page is a hero banner (title plus a "mood barcode", one stripe per chapter) and HTML KPI cards with small SVG pictures, then sections (`section()`), each made of rows (`panel()`): explanation and controls on the left, visualization on the right. **Every new visualization gets a `panel()` with an explanation.**
- `design.py`: the hero, KPI cards (`kpis()` returns the data, `kpi_html()` the markup), cast legend and page CSS (`page_css`, injected with `st.html`). Fonts and page colours are in `.streamlit/config.toml`. `panel()` uses a keyed container (`st-key-panel-N`), which the CSS turns into a card. The owner's raccoon mascot (web-sized copies in `app/assets/`, embedded as data URIs by `design.image_uri`) appears on the start page, as the sidebar logo and tab icon, and in `working_card()` while a book is analyzed; `MASCOT_LINES` needs a line for every `pipeline.STEPS` name (tested). While a book is analyzed, `app/raccoon.py` shows an animated cartoon raccoon (an SVG with CSS animations, drawn in code: no image files) doing each step's job; `raccoon.SCENES` also needs every step (tested).
- **Looks (sidebar "Look": Light / Dark), `app/looks.py`:** both are Streamlit's own themes (`config.toml`), read from the browser's localStorage (`stActiveTheme-<path>-v2`) only when the page loads, so `looks.switch_script` writes that key and reloads once (a 10 s guard stops loops). The open book survives the reload because its sha is kept in the address (`?book=`), and the app reopens it from `results/` (merges and an edited title are not kept). `?look=` is followed only on a session's first run; after that the real theme wins, so Streamlit's settings menu still works. A "Fun" look with a raccoon buddy was built and removed at the owner's request. Note: `st.html` strips inline SVG of some kinds (that buddy had to be drawn in by script).
- **About:** `design.ABOUT` holds the owner's short bio (from their LinkedIn) and links; `design.about()` shows it on the start page and as the last section ("About", also in "Jump to"). It says the site is a passion project made for fun.
- `charts.py`: the Plotly figures. `THEMES` colours come from the dataviz skill's palette, validated for colourblind safety in light and dark mode.
- **Colour rule (the owner asked for it): the 8 categorical `series` colours belong to characters only.** `character_colors` ties each colour to a mention rank (never to selection order), and everything uses it: every chart, the KPI and chapter cards, the sidebar legend, and the 3D scenes (`color` in `scene_data`, dark-mode hex). Charts about something that isn't one character (pairs, places, turning points) use neutral ink, and Streamlit's `primaryColor` is a neutral slate for the same reason. Mood is always the red–gray–blue diverging scale. Emotion families have their own colours in `EMOTION_ORDER` (warm ones first), an order that passed the dataviz validator for stacked neighbours in light and dark mode; re-validate if you reorder or recolour them. Never hard-code emotion positions (the constellation's warm/cold axis uses `WARM_EMOTIONS` by name).
- **Offline:** the owner wants no outside services: `analyzer/__init__.py` sets `HF_HUB_OFFLINE`/`TRANSFORMERS_OFFLINE` (models come from the local Hugging Face cache; `BOOK_ANALYZER_ALLOW_DOWNLOADS=1` lifts it for a first download). Never add a cloud API. The page still fetches fonts (Google Fonts) and Three.js (jsDelivr).
- **3D views:** `explore3d.py` turns the (merged) analysis into a small JSON summary (`scene_data`) and fills it into the `explore3d.html` template (`__DATA__`, `__SCENE__`), shown with `components.html`. Each scene is one Three.js function (r160 from jsDelivr, so it needs internet) on a dark stage. The owner's order on the page (`SCENES`): Emotion crystal, Character constellation, Story road. The constellation also shows dialogue (`analyzer/dialogue.py`): each link carries `ab`/`ba` (lines each says to the other; pairs that talk at least `MIN_TALK` lines get a link even without `MIN_LINK` shared moments), drawn as sparks in the speaker's colour flying from speaker to listener (more sparks = more lines), with "N lines" tags and a "Talks most with" line on the selected character's card. The KPI row has no mention counts (owner's choice): a "Talks the most" card took the Mentions card's place. The first scene, **Story road**, draws `progression.story_arc` as a road over a landscape: height is the smoothed mood, colour is each chapter's mood, every chapter gets `PER_CHAPTER` units of road (long books get a long road; the opening view shows its first `VIEW` units), with signposts at turning points, gates at act starts and a Travel button. (The owner disliked the earlier tower "skyline".) The road replaced the 2D "Story arc" chart; a "Timeline" chart and a "Relationship DNA" scene were removed as duplicates of other panels (owner's choice): avoid adding views that repeat what another panel shows. Beside the road, `design.shape_neighbours` names the famous books whose mood curve matches best (`progression.curve_match`) and those sharing the shape; it and the Pace section's comparisons use `streamlit_app.library()`: a `summary()` of each **famous book in `data/`** with a saved analysis (cached per file; uploads are deliberately left out so they stay private if the site is ever shared). Also beside the road, `design.story_shape_card` shows `progression.story_shape`: the sentence mood smoothed over a fifth of the book, correlated (after standardizing, so only the shape counts) with six straight-line templates in `STORY_SHAPES`; below `WEAK_FIT` it says the book "follows its own path" instead of forcing a label. The road's **walking cast**: `explore3d.presence` gives each character their share of each chapter's character mentions (moving average over ±1 chapter); in the scene, up to 8 characters with avatars walk just ahead of the traveller while their presence is above `ENTER`, and glide off to the roadside and fade when it drops. First-person narrators ("I") are not counted as mentions, so they barely walk. The road's **landscapes**: `analyzer/landscape.chapter_landscapes` reads each chapter's setting (town, countryside, forest, mountains, desert, water, marsh, snow) from clue-word lists (`LANDSCAPES`, plurals count), averaged with the neighbouring chapters; a chapter without clear clues (`MIN_CLUES`, `MIN_DENSITY`) keeps the previous landscape. Computed at render time from the sentences (instant, no model, no re-analysis). In `explore3d.html`, `LAND_LOOK` gives each landscape a ground colour and low-poly `PIECES` (instanced, seeded so they never move); the land shape blends between chapters in `groundAt` (mountains rise away from the road, water and marsh sink under one water sheet). A new landscape needs a word list, a label and a `LAND_LOOK` entry (a test checks this). The road's **weather**: `analyzer/weather.chapter_weather` reads storm, rain, snow, fog, wind or sun from weather words (with -s/-ing/-ed/-y forms; storm words absorb rain words), per chapter only. Weather is never carried over, and a chapter needs `MIN_CLUES` words at `MIN_DENSITY` so one metaphor ("a storm of feeling") doesn't count. In the scene, each such chapter gets a small cloud over the road with animated rain or snow, lightning (storm), fog banks, blowing leaves (wind) or a sun (`skyMoves`, frozen when the browser asks for reduced motion). The clue counting is shared with the landscapes (`landscape.word_lookup`, `chapter_clues`). The road's **shape**: `analyzer/route.chapter_routes` reads straight (avenue, highway, causeway), winding (winding, twisting, maze) or steep (climb, ascend, uphill) from travel words, per chapter. Height stays the mood (the owner's road = mood arc), so these only bend the road sideways: `ROUTE_SHAPE` in the scene gives [bend size, bend speed, zigzag]; `PHASE` accumulates the bend speed chapter by chapter so a change never makes the road jump, and steep chapters blend from a sine into a triangle wave (switchbacks).

- **Character avatars:** `analyzer/appearance.describe()` reads each main character's look from sentences that mention only them (hair colour, age words compared with the book's average, bride/spectacles/beard, a job seen in ≥2 chapters, gender from titles/pronouns, the book's world: period/fantasy/modern) and records the evidence. `app/avatars.py` draws an SVG portrait from it, filling unknowns from the name as a seed, on a ring in the character's colour. `streamlit_app.cast_for()` makes them once per session (book, merges, colour mode); they appear in "The cast" strip, KPI and chapter cards, the sidebar legend, the mentions chart, the network, and the 3D cards and crystal. It runs at render time (no `ANALYSIS_VERSION` bump needed)..

Changes that touch several files:
- **New 3D scene:** an entry in `explore3d.SCENES` (and `EMOTION_SCENES` if it needs emotions), a JS function plus its entry in the dispatch map at the end of `explore3d.html`, and a `SCENE_HELP` text in `streamlit_app.py`.
- **New panel or section:** `tests/test_app.py` checks the section header order and counts the `#### ` explanation titles; update both.

Checking it:
- `tests/test_app.py` drives the page with `AppTest`. The hero and KPI cards are `st.html`, so tests read `design.kpis()` or `app.get("html")`, not `app.metric`.
- AppTest can't run WebGL. To see a scene, write `scene_html(analysis, scene)` to a file and screenshot it with headless Chrome (`--headless=new --use-angle=swiftshader --enable-unsafe-swiftshader`). A plain `--screenshot` of the live site only catches Streamlit's loading skeleton; drive Chrome over the DevTools protocol (`--remote-debugging-port`, `websockets` is installed) and wait about 20 s instead. With all six scenes on one page, the software renderer may show "could not start" even when a real browser is fine.
- A running Streamlit server picks up edits to `streamlit_app.py`, but not to the modules it imports (`charts.py`, `design.py`, `explore3d.py`): restart it.

## Gotchas

- **Keep `transformers<5` and `datasets<5`** (pinned in `requirements.txt`): fastcoref crashes with version 5 of either.
- **Memory:** this machine has the Windows page file off, and the owner's read-aloud voice server (`pythonw … piper_server.py`, never kill it) reserves ~2.6 GB, so often only ~2–3 GB is left. Out-of-memory can show up as a Windows "access violation" crash, not a Python error. Don't load several big models in one process, and don't run the full pipeline, the website and the tests at the same time. The tests use `en_core_web_sm` (see `tests/conftest.py`) for this reason.
- **OpenBLAS out of memory:** numpy's OpenBLAS reserves a buffer per CPU thread, which crashed the website ("OpenBLAS error: Memory allocation still failed"). Start it with `run_website.ps1` (or set `OPENBLAS_NUM_THREADS=1` for any Python run); setting it inside the script is too late, Streamlit imports numpy first.
- **Speed:** a full novel takes ~7 min (coref ~2 min, sentiment ~3 min, emotions ~2–3 min). Int8 quantization of the sentiment model was tested and rejected: only 71% of sentences kept the same category.
- **Commits:** Windows PowerShell 5.1 mangles double quotes in `git commit -m`. Write the message to a file and use `git commit -F <file>`.
- **Measured accuracy:** coref is ~75% correct on a hand check, and the UI tells users the counts are estimates. Emotions: on 60 hand-judged Great Expectations sentences the old tweet-trained 7-emotion model got ~44/60 and EmoLit ~49/60 (weak at fear; "courage" and "curiosity" over-fire). Tested and rejected: neighbouring sentences as context (worse for both models), larger tweet/social models (no gain, 4–7× slower), `fpianz/sentiment-fiction` for mood (no gain on Dickens, 4× slower). Nicknames and married names (Lizzy/Eliza = Elizabeth, Mrs. Collins = Charlotte) are deliberately not auto-merged; the sidebar merge handles them.
- `components.html` logs a deprecation warning ("replace with `st.iframe`") on every run. It still works; switching is a separate change.
- `data/`, `results/`, `.venv/` and `models/` are gitignored.
